# Compatibility stubs for scripted triggers referenced by vanilla files that this
# mod does not blank via replace_paths (so vanilla's copy still loads), but whose
# original definitions were pure real-world content and were not restored.
#
# is_in_guerilla_war: vanilla's definition was entirely about the Carlist Wars,
# which do not exist in this setting. common/battle_conditions is NOT in
# replace_paths, so vanilla's 00_battle_conditions.txt loads and references this
# trigger 21 times. Defined as a constant "no" - deterministic and semantically
# equivalent to "no such war exists".
#
# DISCLOSED CONTENT GAP (audit #3447): this is NOT a harmless no-op. Vanilla's
# only definition (ip4_carlist_war_triggers.txt) checks
# is_involved_in_journal_entry = je_the_first_carlist_war plus
# has_global_variable = carlist_war_skirmish_phase - both Carlist-War-only state
# that cannot exist here (common/journal_entries is blanked; nothing sets that
# global). Of the 21 references in vanilla's 00_battle_conditions.txt, roughly
# six require this trigger to evaluate = yes to unlock a battle-condition
# variant, so stubbing to "no" permanently disables those variants. That is the
# correct call while no WH-native guerrilla/insurgency mechanic exists, but it
# is a content gap, not a clean equivalence: a follow-up item should design a
# WH-native guerrilla/insurgency flag and re-wire those variants onto it.
is_in_guerilla_war = {
	always = no
}
