# Regenerate the land/sea mask — its coastline does not follow the globe's

| Field | Value |
|-------|-------|
| Type | request |
| Priority | high |
| Status | planned |
| Date | 2026-08-12 |

## Description

The committed `tools/derived/land_sea_mask.png` — the mod's single coastline
authority (user decision #1, 2026-07-25) — has a coastline that does **not** match
the coastline drawn on `terraqueous_globe.jpg`. Running the QA overlay makes it
obvious:

```
python tools/qa_overlay.py terraqueous_globe.jpg --step 1
```

writes `tools/derived/qa_terraqueous_globe.png` — the mask's shoreline (magenta)
over the globe — and the magenta line is bloated, ragged, and wanders far off the
drawn coast, with false-land blobs sitting in open ocean.

Regenerate the mask so its coastline follows the globe's actual drawn shoreline,
then regenerate the committed bitmaps that force their shoreline to it
(`map_data/heightmap.png`, `tools/derived/state_labels.png` +
`state_labels_index.json`) so the committed set stays internally consistent.

## Context

### Root cause (observed, not yet fixed)

The mask is built by `tools/generate_heightmap.py` →
`tools/worldgen/ingest.classify_source` → `tools/worldgen/lut.classify`, which
classifies every source pixel to the nearest of 14 elevation swatches
(`tools/lut/terraqueous_elevation.json`, `sea_band_count: 6`, so bands 0–5 = ocean,
6–13 = land). The failure is at the land/sea boundary:

- The globe renders a pale gray-white **bathymetric continental-shelf** wash that
  fans out from every coast into the surrounding ocean. That pale wash is
  colorimetrically ambiguous between the palest ocean swatch (band 0
  `[210,209,197]`, "< −7000 m") and the pale land swatches (band 7
  `[201,197,160]`, band 8 `[224,210,165]`). Nearest-swatch classification tips
  much of it to **land**.
- Result: the mask's coastline balloons out past the real shoreline onto the
  shelf wash, the coast reads as ragged/fractal, and large false-land blobs appear
  in open water (the Far Ocean, the Ocean of Dread, and the shelves around
  Naggaroth / Lustria / Southland are the clearest).
- The globe *does* draw a crisp dark shoreline line separating land from the shelf
  wash — a human can trace it exactly — but the elevation-band classifier does not
  key off that line.

This is the same ill-conditioned land/sea decision the LUT docstrings have fought
before (the retired `paper_rgb` swatch, the spatial polar rule). The existing
morphological cleanup (`segment.clean_land_mask`, `CANVAS_MIN_BLOB = 256`, close/open
radius 2) and the 3×3 source majority filter are not enough to recover a clean
coast from a boundary that is wrong by tens of pixels in places.

### Why this is high priority

`land_sea_mask.png` is not just one output — it is the coastline authority the rest
of the toolchain reads:

- `generate_heightmap.py` forces the heightmap shoreline to it (`encode_heightmap`).
- `generate_state_labels.py` tiles the land area of it; `validate_map.py --labels`
  checks the tiling is exact.
- `generate_rivers.py` reads it.
- **`fit_registration.py` uses it as the silhouette objective** — so every source
  registration is scored against this coastline. The open sibling request
  [world-map-refit-sources-onto-reprojected-globe.md](world-map-refit-sources-onto-reprojected-globe.md)
  explicitly assumes the mask coastline is correct and "nothing moves a shoreline".
  That assumption is what this request corrects; the refit is best sequenced
  **after** this lands, or it fits sources to a wrong coast.

### A canvas-space reference already exists

`sources/terraqueous_globe_reprojected.png` is a faithful Miller reprojection of the
globe at exactly canvas size (8192×3616 = `WIDTH × HEIGHT`, no geometry edits — user,
2026-08-12). It is geometrically identical to the on-the-fly NE-II→Miller reprojection
the toolchain already computes, so a land/sea decision can be made directly in
canvas space against it with no reprojection step. The user is already hand-painting
on a copy of it (`terraqueous_globe_reprojected - rivers.paint/.png`), so a
hand-marked coastline layer would fit the established rivers workflow.

## Plan

### Diagnosis correction (what the problem actually is)

The request was written as a **coastline** problem ("the mask's coastline does not
follow the globe's"). Rendering the QA overlay
(`python tools/qa_overlay.py terraqueous_globe.jpg`, and full-res zoom crops) and
inspecting the committed mask **disproved that**: the coastline tracks the drawn
coast well — the magenta shoreline hugs the real coast, small archipelagos (Broken
Lands, Sun Island, Stars Archipelago, Tol Elasor) are traced, and there are no
false-land blobs floating in open ocean. The shelf-wash "bloat" the request
theorised is not the visible failure.

The real defect (identified by the user) is **false inland water**: 176 enclosed
(non-ocean-connected) water bodies — 137,641 px, 0.465% of canvas — that are
misclassified **rivers** (drawn in ocean-blue) and **flooded marshes** (marsh
gray-green classifying to a shallow-ocean band). The largest is a 14,261-px blob
sitting squarely on the **Marshes of Madness**, with drawn river courses trailing
off it into the Badlands as skinny "lakes". This was confirmed visually
(`tools/derived/lake_empire_big.png`, `dbg_inland_on_globe.png`,
`dbg_lake_catalog.png`).

The coastline, the 14-band LUT, the NE-II fit, the polar-waste rule, and the
shelf-wash colorimetry are all **fine and untouched**. Every genuinely-wanted sea
(Ulthuan's Inner Sea, and every named gulf/sea) is already correct — it is part of
the single 18.6M-px ocean component (Ulthuan's Inner Sea connects to the ocean
through its straits), so it is untouched by any inland-water fix.

The three candidate approaches in the Investigation (hand-mark / better classifier
/ trace shoreline) were all aimed at the *coastline* and are moot: the coastline is
correct. The mechanism below is a targeted enclosed-water reduction instead.

### Objective

Fill every enclosed inland water body to **land**, except a committed allowlist of
10 genuine water bodies the user curated, which stay **water** — so the mask stops
inventing rivers-as-lakes and flooded-marshes while preserving the real lakes. Then
regenerate the committed bitmaps that derive from the mask so the set stays
internally consistent.

### Steps (ordered)

1. **`tools/config/inland_lakes.json`** (new) — committed allowlist:
   `{ "note": "...", "bodies": [ {"name", "seed":[x,y], "kind":"lake"|"sea", "note"} ] }`
   with the 10 rows above. Hand-authored geographic data (like a registration
   seed), byte-stable and deterministic; iterated in sorted `name` order.

2. **`tools/worldgen/schema.py`** — add `InlandLake` + `load_inland_lakes(path)`,
   validated on load exactly like the other schemas: `seed` within the canvas,
   `kind ∈ {lake, sea}`, non-empty unique `name`s. (schema.py is the established
   validate-on-load home; a local loader in the generator is the fallback.)

3. **`tools/worldgen/segment.py`** — add **additive**
   `keep_ocean_and_lakes(mask, keep_seeds, wrap_x)`: wrap-aware label of the water,
   ocean = the largest component, keep = ocean ∪ every component containing a
   keep-seed, set all other water → land. Deterministic (`ndimage.label` + sorted
   seeds, no RNG). `clean_land_mask` and its default signature are **unchanged**, so
   the `run_fixture.py` ingest/boundary fixtures that drive the shared code are
   unaffected.

4. **`tools/generate_heightmap.py`** — after the existing
   `land = segment.clean_land_mask(...)` call, load `inland_lakes.json`, resolve
   each seed to its water pixel, and apply
   `land = segment.keep_ocean_and_lakes(land, keep_seeds, wrap_x)`. **Assert each
   seed lands on water after cleanup** (fail loudly otherwise — clean_land_mask's
   close/open runs first). Log kept-vs-filled body counts and areas (measured, not
   assumed, per the file's house style). The new step subsumes the sub-256 lake
   fill; `min_island_area` (`CANVAS_MIN_BLOB`, archipelago preservation) is
   unchanged. Update the module docstring's pipeline description.

5. **Regenerate the committed bitmaps**, in order:
   - `python tools/generate_heightmap.py` → `tools/derived/land_sea_mask.png` + `map_data/heightmap.png`
   - `python tools/generate_state_labels.py` → `tools/derived/state_labels.png` + `state_labels_index.json`
   - `python tools/generate_rivers.py` → `map_data/rivers.png` (**in scope** — it
     reads the mask + mask-forced heightmap as the coastline authority, so filling
     the false marshes/rivers moves its drainage; confirmed by reading
     `generate_rivers.py:load_working_grids`).

6. **(Recommended)** add a focused `run_fixture.py` boundary case for
   `keep_ocean_and_lakes` (ocean + one keep-seeded lake + one un-seeded lake → the
   un-seeded one fills, the seeded one survives), so the new function is
   regression-pinned like the rest of `worldgen/`.

### Design decisions
- **Keep by committed interior seed, not by area threshold or body index.** A size
  threshold cannot separate the 14k-px false Marshes blob from a ~4k-px real lake,
  and connected-component labels are not stable across regenerations. A seed pixel
  is stable, auditable, and deterministic.
- **#5 kept as water in the mask, tagged `sea`.** The mask is binary; the
  navigable-sea-vs-impassable-lake distinction is a downstream `default.map`/state
  property, recorded via `kind` for the S3b pass.
- **Additive `segment` function; `clean_land_mask` default behaviour unchanged.**
  Keeps the shared ingest/boundary fixtures green without a fixture rewrite.
- **No LUT / classifier / reprojection / coastline change.** The coastline is
  measured-correct; this is purely an enclosed-water reduction. This corrects the
  request's Investigation, which assumed the LUT land/sea split was the failure.

### Edge Cases
- **Seed lands on land after morphology.** Seeds are component-centroid water
  pixels (expected stable), but `/build` must assert each is water post-cleanup and
  fail loudly otherwise, rather than silently dropping a lake.
- **`generate_state_labels` / `validate_map.py --labels`** must still tile exactly
  with 10 interior water bodies present. Lakes are simply "not land"; confirm the
  label validator treats enclosed water consistently (verify, don't assume) — it is
  the `--labels` gate.
- **rivers.png.** The drawn rivers become land, but `generate_rivers` derives its
  own channels from heightmap drainage, so mouths still reach the coast by
  construction. Kept lakes are water and render at the sea index — acceptable for
  this pass (their in-game lake behaviour is S3b).
- **Determinism.** New code is RNG-free and byte-reproducible; seeds are committed
  data. `sources.py --verify` is unaffected (no source added or edited).
