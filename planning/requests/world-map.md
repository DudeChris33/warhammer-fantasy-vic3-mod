## Description

Replace Victoria 3's Earth with the **entire known world of Warhammer Fantasy** — the physical map layer only. This covers everything the engine treats as geography:

- **Province bitmap + heightmap** (`map_data/provinces.png`, heightmap set, rivers)
- **State regions** (`map_data/state_regions/`) — land states and single-province sea zones
- **Strategic regions** (`common/strategic_regions/`) — land theaters + water regions
- **Geographic regions** (`common/geographic_regions/`) — lore-level groupings with script-list `short_key`s
- **Adjacencies & straits** (`map_data/adjacencies.csv`, `common/strait_definitions/`)
- **Terrain** (`map_data/province_terrains.txt` + `gfx/map/terrain` masks)
- **Map visual layers** (`gfx/map/` water, textures, spline_network, map objects, `content_source/map_objects/`)
- **Localization** for every state, sea, hub, and region name
- **A minimal throwaway political scaffold** (placeholder tags + state/pop history + `replace_paths`) whose only purpose is making the game boot into a session so the map can be validated per [testing.md](../../.claude/rules/testing.md)

Decisions pinned with the user (base set 2026-07-19; art-source + automation revised 2026-07-20):

1. **Extent: entire known world** — Old World (Empire, Bretonnia, Kislev, Norsca, Tilea, Estalia, Border Princes, Badlands, Worlds Edge Mountains), Ulthuan, Naggaroth, Lustria, Southlands, Darklands, Mountains of Mourn, Ogre lands, Grand Cathay, Ind, Khuresh, Nippon, Eastern Steppes, and the oceans between. How the polar Chaos Wastes are represented (impassable ring vs. partially playable) is a `/plan` decision.
2. **Art source: generated by Claude in code from canon references** *(revised 2026-07-20 — supersedes the original "hand-painted by a human" framing)* — the province bitmap, heightmap, and rivers are produced **programmatically by generator scripts I author**, using published Known World cartography (Warhammer Fantasy Wiki / Lexicanum, the GW Old World map, the Total War: Warhammer campaign map) as **geometric reference only**. We derive our own bitmaps; no art files are copied from other games or mods.
3. **Density: vanilla-scale** — target the same order as base game (~40k provinces, several hundred land states). Vanilla models the whole Earth at this density on the same canvas, so the whole Known World at vanilla density is an equivalent workload.
4. **Test scaffold: yes** — minimal placeholder political layer included, explicitly throwaway.
5. **Automation-first / minimal human involvement** *(added 2026-07-20)* — a secondary project goal is near-zero human work past the planning phase. I generate every file that *can* be generated in code. The only remaining human steps are the ones that require the Victoria 3 desktop client, which cannot be driven in this environment (browser automation only, no desktop GUI control): running the in-game **map editor** heightmap repack, the optional `terrain.regenerate` console command, and launching a session for `error.log` validation. I ship a precise click-by-click **runbook** for these; the user executes them and I commit the resulting outputs. Whether to instead invest in a fully-headless binary-generation pipeline was considered and **declined** in favor of this minimal-manual approach.

The map pipeline splits cleanly into what I can generate in code and what the Victoria 3 client must produce. Verified against the [Victoria 3 Map modding wiki](https://vic3.paradoxwikis.com/Map_modding) and the [packed_heightmap forum thread](https://forum.paradoxplaza.com/forum/threads/how-to-make-packed_heightmap.1574406/):

|---|---|---|
| `provinces.png` | Generator script (segmentation from reference coastlines; wiki explicitly discourages hand-mapping and expects tools) | **Claude — code** |
| `heightmap.png` (16-bit grayscale, 16384×7232) | Generator script from reference elevation/relief | **Claude — code** |
| `rivers.png` | Generator script (Paradox river color convention) | **Claude — code** |
| `default.map`, `adjacencies.csv` | Generated from province/sea analysis + templates | **Claude — code** |
| `state_regions/*.txt`, `strategic_regions`, `geographic_regions`, `strait_definitions` | Generated from province→region assignment tables | **Claude — code** |
| localization `.yml` (states, seas, hubs, regions) | Generated from a name table (canon names where they exist) | **Claude — code** |
| Scaffold (`country_definitions`, `history/states`, `history/pops`, placeholder culture/religion) | Generated to cover every land state | **Claude — code** |
| `province_terrains.txt` | Either written directly by script, **or** the game's `terrain.regenerate` console command (outputs to `Documents/Paradox Interactive/Victoria 3/generated/`) | Claude-code preferred; console = **human game step** |
| `packed_heightmap.png`, `indirection_heightmap.png`, `heightmap.heightmap` | **In-game map editor** heightmap repack + save — no documented headless/CLI path; game does **not** regenerate on load | **Human game step** |
| `nodes.dat` | Map-editor-generated binary (adjacency/pathfinding graph) | **Human game step** |
| `gfx/map` object locators + `.bin` caches | Map-editor "generate objects" pass | **Human game step** |
| Session-boot `error.log` validation ([testing.md](../../.claude/rules/testing.md)) | Launch game, load a session, read log | **Human game step** (I can launch + read the log via PowerShell for load-time parse errors, but "load into a session" needs UI interaction I can't perform) |

**Net human footprint:** a handful of button clicks in the map editor + one validation session, driven by a written runbook — not hand-authoring of any content. This is the whole point of the automation-first decision.

**Reproducibility requirement (new):** because the source of truth is generator scripts, the scripts themselves (under `tools/`) and a `tools/MAP_RUNBOOK.md` are committed deliverables — the entire map must be regenerable from source + a documented manual pass, not a pile of opaque binaries.

### Design Decisions

- **Canvas identical to vanilla** (8192×3616 / 16384×7232, tile_size 65): Exether-proven on 1.13; changing dimensions buys nothing and risks defines/papermap breakage.
- **`wrap_x = yes`**: vanilla + Exether precedent; lore-consistent circumnavigation. `heightmap.heightmap` internals (`should_wrap_x`, `level_offsets`) are whatever the 1.13.8 editor writes — never hand-tuned.
- **Chaos Wastes — hybrid fringe** (user-confirmed): canvas top/bottom edges cut inside the polar Wastes exactly as vanilla cuts the Arctic; innermost band = `impassable = { … }` province lists inside ordinary edge states (vanilla Greenland/Sahara pattern, 77 occurrences in vanilla state files); outer fringe (Norscan hinterland, troll country, southern wastes) = playable tundra/snow states reserved for future Chaos content. No all-impassable states — zero vanilla precedent, CTD risk.
- **Voronoi province generation** (user-confirmed): hand-painting 30–45k aliasing-free cells is infeasible; subdividing ~700 human-painted state cells with a seeded, committed tool hits vanilla density while keeping "hand-built from canon" provenance — all source art is ours, no external assets. Wrap-aware distance metric at the x-seam; min-area merge for degenerate cells.
- **Hub auto-pick, manual refine**: city = centroid-most province, port = coastal province facing the state's naval exit sea, farm/mine/wood spread; impassable provinces excluded from candidacy. Refinements are one-line edits later.
- **IDs and file naming mirror vanilla**: land ids 1+ grouped in `map_data/state_regions/NN_<macro_region>.txt` (Empire, Bretonnia, Kislev, Norsca, southern realms, Badlands/Worlds Edge, Darklands, Mountains of Mourn, Cathay, Ind/Khuresh, Nippon, steppes, Ulthuan, Naggaroth, Lustria, Southlands…); seas id 3000+ in `99_seas.txt` (single-province states). Strategic region files `<area>_strategic_regions.txt` + `water_strategic_regions.txt` (water SRs carry only `states = { }` — vanilla precedent); geographic regions `NN_geographic_regions_<area>.txt`.
- **Placeholder economics**: uniform parse-valid values (subsistence farm; `arable_land` ≈ 2× province count; wheat/livestock arable; small iron/logging caps; coastal fishing). Real economy is a later request per the out-of-scope list.

### Edge Cases

- Anti-aliasing / stray colors in provinces.png: impossible by construction (indexed output); validator scans anyway for colors absent from all state files, both directions.
- Voronoi degenerates (sub-threshold or disconnected cells): min-area merge in generator; validator flags 1-pixel provinces.
- Seam states at x=0/x=8191: generator treats x cyclically (`wrap_x = yes`); painter guidance: only wrap a state across the seam if genuinely contiguous.
- Coastal state without reachable sea / landlocked state with port: validator forbids `port`/`naval_exit_id` without coastal pixels and requires them with.
- Hub on impassable province: excluded at generation; validator re-checks.
- Editor sessions rewriting generated files (`province_terrains.txt`, locators): review `git diff` after every editor save; commit only intended regenerations.
- Vanilla content referencing dead tags/states after `replace_paths`: the P4 cleanup loop with Exether's override inventory as checklist — fix by filename override, never by editing vanilla files.
- Determinism/MP: every shipped artifact is a static committed file, identical on all clients — MP-safe by construction; generator seed lives in committed config so regeneration reproduces byte-identical output.
