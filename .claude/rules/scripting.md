## Engine reference logs

`docs/*.log` are game-generated reference dumps and are the authority on what script syntax is valid — read the relevant one before writing any script that uses it:

| File | Covers |
|---|---|
| `docs/effects.log` | All valid effects |
| `docs/triggers.log` | All valid triggers/conditions |
| `docs/modifiers.log` | All valid static modifiers |
| `docs/event_targets.log` | Scope-linking event targets |
| `docs/on_actions.log` | Game-fired on_action hooks |
| `docs/custom_localization.log` | Custom localization definitions |

These are read-only references generated by the game itself — never hand-edit them.

## Organization

- `common/` has one subfolder per database (`buildings/`, `cultures/`, `decisions/`, `laws/`, `technology/technologies/`, `scripted_effects/`, `scripted_triggers/`, `script_values/`, `history/...`, etc.). Put new entries in the matching existing subfolder — don't create a new top-level `common/` subfolder unless the database genuinely doesn't have one yet.
- `events/` holds event files as flat `.txt` files (no subfolders currently). Every event file must declare a unique `namespace = <name>` at the top, and every event id must be `namespace.NNNN`.
- Reusable script logic (a check or calculation used in more than one place) belongs in `common/scripted_effects/`, `common/scripted_triggers/`, or `common/script_values/` rather than being duplicated inline.

## `.metadata/metadata.json` `replace_paths`

`replace_paths` can only name folders under `common/`, `events/`, or `map_data/` — those
are the three trees the engine will blank per the loader's own rules; nothing else is a
valid entry.

**Loading behaviour.** A folder listed there is *blanked*: the game does not load vanilla's files
for it at all, so every definition that folder normally provides must be re-authored
(cleaned-generic or WH-native) in this mod's copy, or it simply doesn't exist — this is what the
vanilla-cleanup restoration work is for. A folder **not** listed merges normally: vanilla's files
still load exactly as shipped, and this mod only needs a file there to override or add to that
content. **Do not assume a `common/<folder>` that is empty or absent here is a gap needing
restoration — check `replace_paths` first.** `combat_unit_groups` and
`combat_unit_experience_levels` look like the same class of gap as `scripted_triggers`, but
neither is in `replace_paths`, so vanilla's generic definitions load; a fresh `error.log` is the
only thing that proves otherwise.

A folder goes in `replace_paths` once this mod blanks and/or replaces **every** vanilla
file that folder ships — whether by authoring full replacement content for each file
(same filename, new body) or by leaving some deliberately empty. Once it's listed, the
engine doesn't load any of vanilla's files for that folder at all, so any per-file
"blank" stub that existed only to suppress a vanilla file becomes redundant — remove
those stubs when the folder is added. A folder that only replaces *some* of vanilla's
files for a database (leaving the rest to merge in normally) does not qualify (see
the loading-behaviour paragraph above).

A folder's presence in `replace_paths` is enough: it does not need to exist in git, so no
`.gitkeep` is required for it (Chris, 2026-10-23). That is also why generated, gitignored folders
such as `common/history/{states,pops,population,countries,buildings}` carry none.

## Patterns

- Validate every effect/trigger/modifier against `docs/effects.log`, `docs/triggers.log`, or `docs/modifiers.log` before use — these logs list the exact scope requirements.
- Validate every `event_target:` scope link against `docs/event_targets.log` (Input Scopes / Output Scopes columns). Match input/output scopes exactly — a target used in the wrong scope fails silently or crashes to desktop.
- Validate every `on_action` hook against `docs/on_actions.log`, including its `Expected Scope`.
- Custom localization functions used in loc strings must be defined per `docs/custom_localization.log` before being referenced.
- **Starting pacts must be keepable (#6576).** Every `create_diplomatic_pact` in `common/history/diplomacy/` must satisfy that pact's maintain rules, or it breaks on day 1 and floods "Rivalry broken"/"Vassal broken" notifications (`error.log` `initializefrombookmark.cpp:1430` "cannot be maintained"). Subjects follow vanilla `common/subject_types/00_subject_types.txt`: `vassal`/`tributary` need an **unrecognized** overlord, `puppet`/`protectorate` a **recognized** one, and the overlord must outrank the subject. `puppet`/`protectorate` take only `recognized`/`unrecognized` subjects; a `colonial` (or `company`) subject takes `colony` (vanilla `c:SPA` → CUB/PCO/PHI; first used here by `c:LOT`'s High Elf colonies, #8444). Every subject type accepts only a `great_power`/`major_power`/`minor_power` overlord (`overlord_must_be_higher_rank = yes`). Rank is prestige-based (vanilla `common/defines/00_defines.txt` `PRESTIGE_FROM_*`: tier, GDP, subject GDP, power projection), and `enforce_subject_rank_check` in `common/country_ranks/` makes a minor/major/great rank invalid for a subject whose overlord does not outrank it; whether a pact holds is settled only by the in-game `1430` check. A `rivalry` needs two independent countries on the same recognized/unrecognized rank ladder with the other maintain rules met (`countries_are_valid_rivals`); put cross-ladder enmity in `00_relations.txt` as negative `set_relations`. After any edit there, check `error.log` shows no `1430` lines.

## Naming

- The first established convention is the culture foundation (#3405): zero-padded `NN_<topic>.txt` filenames within a database folder, ordered by loading/reading precedence (e.g. `common/discrimination_trait_groups/00_heritage_groups.txt`, `01_language_groups.txt`, `02_religious_heritage_groups.txt`; `common/religions/00_religions.txt`). When a folder has no such convention yet, pick a clear, descriptive snake_case filename (with or without a numeric prefix, e.g. `buildings_empire.txt`) and stay consistent with whatever is chosen going forward. `common/country_definitions/` and `common/country_formation/` follow that `NN_<region>.txt` shape, one file per Old World region — see [peoples.md](peoples.md).

## Compatibility stubs and partial ports

Applies to `common/scripted_triggers/`, `common/scripted_effects/` and `common/on_actions/` alike.

Two kinds of caller keep calling script this mod declined to restore. Either the calling file
belongs to a folder that is *not* in `replace_paths` (e.g. `common/battle_conditions/`, and the
`gfx/` building/train/ship graphics data), so vanilla's own copy still loads and still calls it; or
the calling file was itself restored into this mod by the vanilla-cleanup epic and its body kept a call that the
restoration pass did not bring across (`is_princely_state`, called from this mod's own
`common/ai_strategies/` files). Both fail the same way and take the same remedy; note which one a
new stub belongs to, since the second is self-inflicted.

Every restoration falls into one of three categories, and the comment above the entry must say
which:

- **Clean port** — the vanilla body depends only on engine-side keys or on content this mod
  actually ships, so restore it verbatim. Record the vanilla file and line.
- **Partial port** — most of the vanilla body ports, but named branches must be dropped. The
  comment must name *exactly* which branches were dropped, why, and what that prunes in play. A
  partial port whose comment only says "adapted" is not acceptable. If dropping the offending
  calls empties an `if` branch outright, drop the branch too rather than leaving an effect-less
  `if`.
- **Inert stub** — an empty body (`{ }` for a scripted effect, `effect = {}` for an on_action,
  `always = no` / `always = yes` for a trigger; all confirmed valid, and vanilla itself ships an
  empty-bodied scripted effect in `00_starting_inventions.txt`). Keep trigger stubs to a constant
  so they stay deterministic, and pick the value matching vanilla's own fallback semantics — a
  trigger that is vanilla's `NOR`-over-everything catch-all (e.g.
  `gfx_has_no_culture_trains_trigger`) stubs to `yes`, not `no`.

### Port-vs-stub decision rule (load-error taxonomy)

What forces a drop is whether the reference is a *hard load error* or merely inert:

| Reference to a missing object | Consequence |
|---|---|
| `has_modifier` / `add_modifier` / `remove_modifier` on an undefined named modifier | **hard load error** — must be dropped or the modifier restored |
| `has_journal_entry` on a missing journal-entry type | **hard load error** — must be dropped |
| `add_journal_entry` on a missing journal-entry type | silently inert — drop for hygiene, but it is not what forces a partial port |

So a body that only *adds* a missing journal entry can be ported and trimmed at leisure, while one
that *checks* a missing modifier or journal entry cannot be ported at all until the object exists.
Prefer restoring the missing object where it is generic (e.g. the nine regency
modifiers, which turned `remove_regency_modifier` from a planned stub into a clean port).

Every stub must record, in a comment above it, **whether it is a true no-op or silently prunes
dependent content** — do not present all stubs as clean equivalences. Most graphics-selection
triggers are genuine no-ops: a false result just falls through to the default visual variant.
`is_in_guerilla_war` in `01_legacy_compat_triggers.txt` is the counter-example and the model for
the disclosure: stubbing it false permanently disables the ~6 vanilla battle-condition variants
gated on it evaluating `= yes`, which is the right call today but is a disclosed content gap with a
follow-up owed. `is_princely_state` is the same shape on the effects/AI side: four
`common/ai_strategies/` branches prune when it returns no.

Compatibility triggers live either in `01_legacy_compat_triggers.txt` (cross-cutting one-offs) or in
a file named after the vanilla file they stand in for (`00_gfx_buildings_graphics_triggers.txt`).
Restored scripted effects follow the second shape only — one file per vanilla file, under vanilla's
own filename (`00_victoria_ip4_scripted_effects.txt`, `00_victoria_ip3_scripted_effects.txt`,
`00_victoria_ep2_scripted_effects.txt`), carrying just the entries that file's live call
sites still need. Restored on_actions go into the existing `common/on_actions/00_code_on_actions.txt`
beside their vanilla neighbours, keeping vanilla's `# Root = …` / `# scope:… =` header comments.
Before adding any of them, grep `common/` for the id — a duplicate definition is a game-log error.

## Vanilla cleanup rules (per folder)

Vanilla files in folders **not** in `replace_paths` still load and reference objects the blanked folders no longer define — that is the `Invalid database object` class in `error.log`. Regenerate `error.log` (load the mod) before scoping cleanup; an old one is stale once `replace_paths` has grown.

- **Producer folder** (in `replace_paths`): restore setting-neutral generic vanilla definitions, stripped of inner missing references. If a change touches most of a folder's files, add the folder to `replace_paths` and ship only the cleaned files rather than `REPLACE:` per definition.
- **Real-world top-level definitions** (`unify_germany`, `meiji_restoration` — named for a real place, person or event): delete wholesale, whatever their inner contents.
- **Keep** references to generic game structure the mod redefines under the *same* vanilla names (interest groups, ideologies, laws, pop types, goods, buildings, techs, generic AI strategies and traits): they dangle only until their folder is built, and that cascade is accepted — do not strip them.
- **Strip** references to genuinely gone content — `cu:`, `rel:`, `c:XXX` tags, `je_`, `geographic_region_`, `sr:`, `heritage_`/`language_`, historical `has_template`. Replace a self-contained condition with an inert `always = no`/`always = yes` (keeps the brace structure).
- The keep/remove test is the resolve-or-dangle criterion in the doctrine below. Real-world specifics are our-world proper nouns (France, the Eiffel Tower, the Holy Roman Empire, the Springtime of Peoples, `character_role_emperor_of_japan`, `geographic_region_europe`); generic members (`has_role_of_type = general`, coups, regencies, government types) stay. The same family can sit on both sides: `gov_dual_monarchy` (Austria-Hungary) went while generic government types stay.
- **A stripped real-world gate makes a government variant shadow its generic sibling (#6642).** The engine takes the first `common/government_types` entry whose `possible` passes, in file order (inferred, not documented: vanilla `01_colonial_administrations.txt:51,64`'s `NOT = { #handled in gov_colonial_administration_spa` only makes sense that way). With its region or culture gate stripped, a real-world variant listed before an otherwise identical generic one wins every time. Delete such a variant rather than strip its gate: #6642 deleted `gov_soviet_dictatorship`, `gov_soviet_single_party_state`, `gov_soviet_republic`, `gov_phalanstere` and `gov_falangist_state`. `gov_free_city` and `gov_warlord_state` lost tag/region gates the same way and were kept because they fit the setting.
- For entries this mod will **repurpose** (reused `gfx/` and script), the neutralize doctrine below overrides the older "delete the gated block" step: neutralize the leaf, keep the scaffolding.
- **Portraits/clothing exception (Chris, 2026-08-27):** Warhammer humans look like real humans, so genes, ethnicities and clothing are not redone. `common/genes`, `dna_data`, `ethnicities` and `culture_graphics` are deliberately *not* in `replace_paths` (vanilla's load). `scripted_triggers` is blanked, but `common/scripted_triggers/00_clothes_triggers.txt` keeps all 165 vanilla trigger names so the `*_clothes*` triggers used by `portrait_modifiers` stay defined without real-world culture/tag refs. 12 character-role triggers are restored (#6639: ruler, military, armed-forces, politician, monarchy, republic, junta, regency, agitator, executive, magnate, plus `european_clothes_trigger`, the WH gate on `has_culture_graphics = european`); the rest stay inert `always = no` stubs, so pops and non-European-graphics characters fall through to default clothing. Vanilla's "generic" templates hide national art (late WW1 coat colourways, an eagle helmet plate), so the newly reachable ones are pinned to generic pieces (`# [#6639] was:`); audit any newly reachable template by decoding its textures and palettes, not by its name. Never overwrite that file with vanilla's.
- **Variable lint (`error.log` `jomini_effect.cpp:1135` "set but never used", `:1139` "used but never set"; #6573).** Policy: every never-set variable the mod reads is neutralized (`always = no  # [#6573] was: ...`; `value = 0` for a value read; a comparison resolves to `always = yes`/`no` as if the unset variable read 0, `no` when a dead sibling already shields it), whether its vanilla setter was real-world content or a generic mechanic (lobbies, strikes, IP4 negotiation, ideology paths, coups, regency, achievements). Set-never-used writers and their `remove_variable`/`change_variable` companions are commented out with `# [#6573] removed:`. Restoring a system means un-neutralizing by grepping `[#6573]`. Two variables are vanilla-owned and cannot be fixed here (`fireworks_variable`, `prison_time_var`: vanilla gfx and scripted_lists read them). Recount with `grep -cE "jomini_effect\.cpp:113[59]" error.log`; expected 0 x :1135 and 2 x :1139.
- Progress lives on the board (epic #3292 and its children), not here.

## `gfx/` real-world-reference keep-list + neutralization

The authored `gfx/` override files — `gfx/portraits/portrait_modifiers/01_{accessories,beards,
clothes,hairstyles,headgear}.txt` (5), `gfx/portraits/portrait_animations/animations.txt`,
`gfx/map/front_entities/*` (3) and `gfx/map/city_data/city_types/*` (10) — reuse vanilla
portrait/city selection wholesale because the Warhammer world resembles ours. `gfx/` is **not**
blankable (only `common/`/`events/`/`map_data/` are eligible for `replace_paths`), so vanilla's gfx
always merges underneath and these files only override specific vanilla filenames. That makes
resolution **per-reference, never per-file deletion**: deleting an override re-exposes vanilla's
real-world refs and reverts prior fixes.

### The criterion — generic concept vs. real-world specific, applied by resolve-or-dangle

Keep a script reference when the referenced id **resolves** to something this mod (or still-loaded
generic vanilla content) actually defines; treat it as a real-world specific to neutralize when it
**dangles** because it named real-world content the conversion deleted/never authored. The axis is
generic-vs-specific, **not the trigger family** — the same family sits on both sides (a generic
`has_law = law_type:law_monarchy` stays; a `culture = cu:japanese` goes). Check each id against the
**engine authority for its family**, not against a name or a planning doc:

| Family (live token) | Resolves against | This mod |
|---|---|---|
| `cu:<id>` / `culture[= /?=]` / `has_culture` / `country_has_primary_culture` | `common/cultures/*.txt` | 55 WH cultures; every real-world id dangles |
| `c:<TAG>` / `exists`/`home_country`/`owner`/`was_formed_from`/`is_unification_candidate`/`c:TAG ?= {…}` | `common/country_definitions/*.txt` (**not** `planning/tag_registry.md`, which lists unauthored placeholders) | WH tags; `MOR`/`PRA` coincidentally resolve (Massif Orcal/Praag) but are **force-neutralized** — Chris's call, they'd otherwise drive real-world Moroccan/Prussian art for those polities |
| `rel:<id>` / `religion` / `country_has_state_religion` | `common/religions/00_religions.txt` | `cult_of_*`/`old_faith`/…; catholic/hindu/shinto/… dangle |
| `has_variable` / `has_global_variable` | (runtime flags) | real-world event flags set only by blanked `events/*` → permanently unset → always neutralize; **never a load-error, but the load-time variable lint (`jomini_effect.cpp:1139` "used but never set") does flag them in `error.log`** — the static classifier is still the completeness gate, the lint a cross-check |
| `is_in_geographic_region` | `common/geographic_regions/` (empty) | always dangles |
| `has_role = character_role_emperor_of_japan` | `common/character_roles/` (not blanked → resolves) | **force-neutralized** — resolves but real-world |
| `has_law` / `has_technology_researched` / `has_ideology` / `has_trait` / `has_role_of_type`, all `graphical_culture`/`graphics`/`dna_modifiers` scaffolding, and every real-world-*named*-but-defined `*_clothes`/`*_buildings` scripted_trigger | resolve → **KEEP** | name is not the test: `spanish_clothes_pop_trigger`/`french_buildings_trigger` resolve and stay |

`city_types/*` carry no live real-world refs (see the inventory in [interface.md](interface.md));
read-through only, no edits.

The same technique is used outside `gfx/`. Neutralized `# was:` sites: `gfx/portraits/**`
(610 tags), the `gfx/map/` files (20), `common/ai_strategies/` (6),
`common/dynamic_treaty_names/00_dynamic_treaty_names.txt` (2), `common/scripted_triggers/`
(1) and `common/political_movements/` (1) — counts from `git grep -c "was:"` at audit time,
so re-measure rather than trust them.

### Neutralize, don't delete

The mod will **repurpose most of these entries** for WH content later, so **preserve all scaffolding**
(the variant, its `dna_modifiers`/art template, and every `modifier`/`OR`/`AND`/`NOT` wrapper) and
neutralize only the dangling **leaf condition** by replacing it with `always = no`, tagged
`# was: <original>`. This is **behaviour-neutral**: a comparison to a non-existent id is
always false, and so is `always = no`, so every boolean wrapper keeps its truth value
(`NOT { always = no }` stays always-true, an `OR`-branch stays dead, a required gate stays
never-firing) — and it also fixes the load-errors that strong `cu:`/`c:` links throw. A
`c:<TAG> ?= { … }` scope-switch block collapses to a single `always = no` (naming the tag in a
comment). **Do not delete whole variants/modifiers/branches** — that was the earlier approach and Chris
reversed it mid-build (#3662, 2026-09-06). Tag each site `# [#3662] was: <original>` (or the current item)
so the original can be restored. Repurposing later is a one-line swap of `always = no` for the real WH trigger.

**Governance principles are renamed through loc, never deleted.** Every `common/laws/00_governance_principles.txt` law is referenced as `law_type:<id>` in 11-30 other files, so removing one is a hard load error; modern-sounding principles (presidential/parliamentary/council republic, corporate state, social monarchy) get new display names in `localization/replace/english/wh_laws_governance_l_english.yml` (#6575) and keep their ids. Their government-type variants' names, descriptions, the `RULER_TITLE_PRESIDENT`/`RULER_TITLE_CHIEF_EXECUTIVE` titles and the two elective transfer-of-power labels are overridden in `localization/replace/english/wh_government_types_l_english.yml` (#6642). Exception kept on purpose: `gov_contechne` and its `RULER_TITLE_ARCHMAGOS`/`RULER_TITLE_MAGOS` titles are a Warhammer 40K easter egg for a technocratic theocracy and stay as named (Chris, 2026-10-21). `law_chiefdom` and `law_elder_council` are widened from decentralized countries to tribal realms (`wh_country_is_tribal_realm`, #9037) and must not be re-gated to `is_country_type = decentralized`; the generator, not the politics effect, activates `law_chiefdom` (a culture test in that effect would make building history mark every tag unresolved).

### Verification (no offline validator exists for gfx script)

A static live-ref classifier that enumerates **every** reference family (not a pre-listed subset —
that is how `has_variable`/`was_formed_from` were nearly missed) and computes resolve/dangle against
the per-family engine authority above is the completeness gate; it must report **zero** live
(non-comment) dangling occurrences. Pair it with a brace-balance / entry-count check (entry counts
must be **unchanged** — nothing deleted) and a malformed-pattern / empty-block scan, then the
mandatory in-game `error.log` gate ([core.md](core.md)). error.log alone under-counts (only
the first parse/lookup failure per file surfaces, and `has_variable` never errors), so it is the
no-regression authority, not the completeness authority.

## Forbidden

- No non-deterministic effects (see [core.md](core.md) Guardrails, *Determinism*).
- No effect/trigger/modifier/event target not confirmed in `docs/*.log`.
- No hardcoded display text — route all user-facing strings through localization keys.
