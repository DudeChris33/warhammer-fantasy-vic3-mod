## Canvas, scope and sources

- The canvas is **8192×3616**, a Miller projection pinned to a line the user drew; the frame constants live in `mapgen/config/canvas_frame.py` and `map_config.py`. Vanilla's own frame is the reference for formats and sizes.
- **Scope**: the drawn Old World land regions, all oceans (global), and placeholder regions for the out-of-scope land, seeded by `mapgen/config/out_of_scope_continents.json` (`land_regions_index.json` records `drawn_regions` vs `placeholder_regions`). **Ulthuan (2026-10-11) and the High Elf colonies (2026-10-12) are in scope (Chris)** and drawn. `generate_provinces.py` calls a region drawn when it sits in the dense network of state borders (`land_provinces.drawn_mask`); land that rule cannot find (an island with no interior border, a cap cut off a mainland by one stroke) is listed in the hand-authored `mapgen/config/in_scope_additions.json`, by box or by point, with the realm it takes (`worldgen/scope_additions.py`, read by `generate_provinces.py` and `generate_land_regions.py`). Colonies take the realm of the land beside them. Ulthuan's boundary source is ChaosRobie's expanded parchment, placed by the `cr_combi_expanded_map_ulthuan` paired-anchor-dot registration (fit accepted 2026-10-12; `sources/ulthuan/`, workflow in `mapgen/SOURCES.md`). `mapgen/adjust_ring_borders.py` redraws his parchment state borders for the canvas's land (ring-parallel lines at even depths, coast ends on the coast) as a gitignored proposal (in `scratchpad/`) for the `borders` layer, which stays his to draw. `mapgen/propose_cr_borders.py --landmass <name>` (#8210) is the landmass-agnostic tool for the rest of the world: it places ChaosRobie's whole-world region lookup on our land **by itself, with no dots from Chris** (2026-10-14), uses its regions as a *guide* (not borders to reproduce), snaps to rivers and impassable edges, and writes a `borders` proposal, a review render and a per-state table to `scratchpad/`. Its outputs are proposals, never sources; the layer stays his.
- `sources/` is **git-ignored and local-only** (bulky imagery kept out of git). Provenance is the SHA-256 manifest `mapgen/SOURCES.md` plus `mapgen/registration/*.json`; `python mapgen/worldgen/sources.py --verify` checks it. A hand-painted GIMP master's OpenRaster `.ora` export is read **by layer name** through the committed `mapgen/config/source_layers.json`. Choosing, adding or marking up imagery is Chris's; `--update-manifest` follows an intentional source change and is never a side effect of a generator run.
- Registration records (`mapgen/registration/*.json`) are machine-fitted, not hand-written: edit a seed in `mapgen/registration/seeds/` and re-derive with `python mapgen/fit_registration.py --seed <stem>`.
- Better source beats more tuning: if an extraction is capped by its source, say so and ask for imagery rather than tuning thresholds.

## The tooling loop

Run this autonomously to convergence: edit a generator, LUT, seed or hand-authored input → re-derive (`fit_registration.py`, then the regeneration pipeline below) → run the offline gate → **render the map into `scratchpad/` and send the PNG** → read it, diagnose, go again. A green gate is a precondition, never a stopping point; the rendered map is the real gate and Chris's verdict is final (see [core.md](core.md)). Review renders overlay cells on the reprojected globe (`terraqueous_globe_reprojected.png`, 1:1 with the canvas), never the native `terraqueous_globe.jpg`.

## Offline gate (pre-commit lint)

One-time setup: a local `mapgen/.venv` (git-ignored), deps pinned in `mapgen/requirements.txt`. Before committing anything under `map_data/`, `common/strategic_regions/`, the map localization, or the source-registration data, run:

```
python mapgen/read_state_ownership.py --check     # state_ownership.json is current with the painted PNG + map_data
python mapgen/generate_state_history.py --check   # common/history/states is current with state_ownership.json
python mapgen/generate_pop_history.py --check     # common/history/pops + population are current with mapgen/config/pop_history and resolve
python mapgen/generate_country_history.py --check # common/history/countries is current with the owners + tiers
python mapgen/generate_map_locators.py --check    # the five map-object locator files are current with state ids + hub provinces
python mapgen/generate_building_history.py --check # common/history/buildings is current, resolves, and passes the tech gate (runs the verifier)
python mapgen/validate_building_history.py         # independent tech-gate verifier on the emitted buildings + current country history
python mapgen/worldgen/sources.py --verify        # source manifest SHA-256 + registration cross-checks
python mapgen/validate_map.py --province-bitmap    # bitmap tiles the mask, agrees with its index and the sea layer
python mapgen/validate_map.py --sea                # sea engine files (colours, sea_starts, grouping, loc)
python mapgen/run_fixture.py --check               # regression-checks the toolchain against synthetic fixtures
python mapgen/validate_map.py                      # full crosscheck (needs both sea + land state files)
```

All must pass before the in-game `error.log` check; they catch the offline-detectable error class first and do not replace the game load. `validate_map.py --labels` lints the state-label layer instead of the province map. `validate_map.py --province-bitmap` prints non-blocking `WARNING`s (a separate channel that never fails the gate): a lake over `lakes.OCEAN_WARN_FRACTION` of the world ocean (possibly a sealed-off sea) and one below `lakes.LAKE_REPORT_MIN` (likely fill speckle — drop or redraw, never merge). `run_fixture.py --check` covers every generator module against committed fixtures, independent of `sources/`. Full `validate_map.py` also runs the per-state economics check (#3678: rules, worksheet cross-check; non-blocking warnings for `arable_land` below 10 and states still on default economics) and checks `common/history/states` against `map_data`, `state_ownership.json`, the defined (non-dynamic) country tags and the homelands (every `add_homeland` id must be a `common/cultures` id and equal the owners' `cultures`); an unowned or out-of-scope state without its `c:UNO` block fails as an owner mismatch, and an owner tag with no definition (`UNO` included) is held back by the generator and fails the gate (`HELD_BACK_IS_ERROR`). A `--check` that byte-compares a generated text file normalizes a BOM and `\r\n` first: `core.autocrlf` checks the committed LF files out as CRLF.

## Regeneration pipeline

The mask moves first; every downstream layer regenerates from it, in this order:

```
generate_coastline_mask.py --from-fill → generate_heightmap.py → generate_rivers.py →
generate_state_labels.py → generate_sea_zones.py → generate_provinces.py →
generate_sea_regions.py + generate_land_regions.py →
read_state_ownership.py → generate_state_history.py → generate_country_history.py →
generate_building_history.py → generate_province_terrains.py → generate_adjacencies.py --write →
generate_arable_heatmap.py → generate_flatmap_textures.py → generate_map_locators.py
```

`generate_climate_zones.py` (#8202) sits off this chain: it needs only `land_sea_mask.png`, `heightmap.png` and the
currents drawing, so it runs any time after `generate_heightmap.py`; its `--states` pass reads the province cut and
so follows `generate_land_regions.py`. Nothing in the chain reads it yet except the dev-only tabulator.

- **Bringing land into scope**: add it to `in_scope_additions.json` (or draw interior borders), then raise `PROVINCE_TARGET` in `generate_provinces.py` in proportion to the drawn area (the formula is in its comment). The target is shared out by area, so left alone every existing state loses provinces to pay for the new land. After `generate_land_regions.py`, `python mapgen/render_state_ownership.py --adopt-new-states` paints the new states unowned on `state_ownership.png` (it touches only drawn states still wholly in the placeholder colour), so `read_state_ownership.py` can run; then `generate_pop_history.py --refresh-weights`.
- **`generate_building_history.py` follows `generate_country_history.py`: any change to country history (tiers, techs, laws) requires re-running it.** **Tech-gate crash rule: a building or production method in a country that has not researched its unlocking tech crashes the game at load, so nothing is emitted unless the tag's `common/history/countries/` file grants it (fail closed; `validate_building_history.py` re-checks independently).**
- **A `generate_land_regions.py` regen that changes state ids requires `generate_map_locators.py`.** Locator `id` is the state id and ids renumber on regeneration, so the old files are wrong by id, not merely stale (#6612).
- **A `generate_provinces.py` or `generate_land_regions.py` regen stales the starting ownership.** `state_ownership.json` and `common/history/states` are colour- and state-keyed, so re-run `read_state_ownership.py` then `generate_state_history.py`; the read may hard-error (a province with no votable pixel, a new state) and need a repaint, which is Chris's.
- **Global starting totals target rough parity with vanilla (Chris, 2026-10-05).** Across the whole map, the mod's starting population (`common/history/pops` + `population`), arable land, resource counts (`state_regions` `arable_resources` / capped resources) and starting building levels (`common/history/buildings`), starting military unit count and starting fleet count should each land roughly equal to vanilla's world totals. Only the totals need to match: the distribution (which states, countries and tags hold them) is free to differ from vanilla. Calibrate the `mapgen/config/pop_history/` and `building_history/` inputs and the per-state economics against it; measure vanilla with the read-only `measure_vanilla_arable.py` (arable) and the vanilla install's `common/history/` and `map_data/state_regions/` (the rest). A total far off vanilla's is a defect to flag, not a design choice to keep.

- The coastline source is a black/white land **fill**, so always pass `--from-fill` (the parity-trace default is legacy, `generate_coastline_mask.py`). `--from-fill` also emits `mapgen/derived/lake_mask.png`; either mode first drops isolated sub-4px land components (`drop_land_specks`, `--speck-max`).
- **A `generate_provinces.py` regen invalidates every downstream, colour-keyed emitter** (sea regions, land regions, province terrains, adjacencies, arable heatmap) even when few provinces moved — always re-run the full chain from `generate_provinces.py` onward, then the offline gate, before committing.
- **Identity is stable across regens.** Province colour = province id in Vic3, so ids must not churn. `province_ids.assign`, `land_state_numbering.assign_state_numbers` and `sea_state_ids.assign` overlap-match against the previously committed output; only genuinely new or removed geometry is reassigned, off a monotonic high-water mark that never reuses a retired id (`id_high_water` in `provinces_index.json`, `state_number_high_water` in `land_state_ids.json`, `sea_id_high_water`/`ordinal_high_water` in `sea_zones_index.json`).
- `--reassign` (on `generate_provinces.py`, `generate_land_regions.py` and `generate_sea_zones.py`) is the escape hatch that re-allocates ids fresh in label order. Pair a province `--reassign` with the land and sea ones, or overlap-matching has nothing to match against and falls back with a loud warning.
- **State borders are frozen; province cuts may move.** State borders are the user-drawn `full.ora#borders` layer on the canvas (consumed directly by `land_provinces.py`). Any paint on that layer is read as a border whatever its colour (`generate_provinces.py` logs a warning for strokes that are not magenta). **Small-state prune**: on `terraqueous_globe_reprojected - small-state-prune.png` (`source_layers.json` key `small_state_prune`) Chris draws a pure-yellow line from a state too small to stand alone to the neighbour it joins. `generate_provinces.py` applies the lines after the province cut, so the provinces do not move and only state membership changes; the merged state keeps the hub rows of its largest member. The sheet must be exported with the adjacency layer hidden (both use the same yellow). A merge across impassable paint leaves the state's passable land in two pieces, which `validate_map.py` rejects until a tunnel adjacency or a gap in the paint joins them; a merge of states with different owners makes a split state, and any `pop_history/state_overrides.json` row for it then needs a `tag`. Redraw provinces through the generator (e.g. to place hubs), never state borders. Merged regions (`mapgen/config/land_region_merges.json`) ship as one province per connected piece.
- `generate_sea_zones.py` runs *before* `generate_provinces.py`, so zone identity across regens is zone-layer pixel overlap. The purple-network zones are authoritative; ocean-current auto-generation is reference-only (its "centre on the current limb" rule is worth keeping).
- `generate_land_regions.py` writes all 20 land files `map_data/state_regions/NN_<stem>.txt`, the per-continent `common/strategic_regions/*_strategic_regions.txt`, `localization/replace/english/map/states_l_english.yml` and `localization/replace/english/map/wh_hub_names_l_english.yml`, plus `mapgen/derived/land_state_ids.json` (STATE-number authority, seeded once by `mapgen/seed_land_state_ids.py` off a committed git ref). Each drawn state's `subsistence_building`/`arable_land`/`arable_resources` come from `mapgen/config/land_economics_worksheet.csv` (empty cell, missing row and every placeholder fall back to `worldgen.land_economics.DEFAULT_ECONOMICS`; rules in `check_economics`, errors reported once); `--rekey-economics` is an explicit authoring action that fixes stale key cells. A worksheet edit forces `generate_land_regions.py` then `generate_building_history.py` (it reads the emitted fields). `generate_sea_regions.py` writes `99_seas.txt`, block-replaces `default.map`'s `sea_starts` and `lakes`, the water strategic regions and `wh_seas_l_english.yml`, and creates a header-only `adjacencies.csv` if absent (never clobbers a populated one).
- **Real-world-equivalent economics (Chris, 2026-10-12).** Every land state's default `arable_land`/`subsistence_building`/`arable_resources`/`capped_resources`/`resource` blocks (placeholders included) are the vanilla totals of the real-world area whose colour Chris gave the WHFB zone in `sources/history/real-world-comparisons-{f,r}.png`, spread over the states by overlapping land area with largest-remainder rounding (`worldgen/real_world_economics.py`, applied in `generate_land_regions.py`). Inputs are the committed `mapgen/config/real_world_equivalents.json` (per-zone vanilla totals) and `real_world_zones.png` (canvas zone index raster, R channel), both written by `mapgen/build_real_world_equivalents.py` (needs `sources/history/` and the vanilla install; re-run when the legend, the drawn Old World or the sources change, `--check` diffs the JSON). A worksheet cell still overrides per column for drawn states. Zones with colour/geometry choices are in that script's `ZONES`/`CELL_ZONE`. The single `STATE_PLACEHOLDER` is the whole undrawn remainder, so it carries many zones' shares (tens of thousands of arable). Supersedes the climate-class approach of the paused arable epic for starting values.
- `generate_province_terrains.py` writes `map_data/province_terrains.txt` (land `plains`, sea `ocean`, lake `lakes`); `validate_map.py --province-bitmap` checks it when present.
- `generate_climate_zones.py` (#8202) is an offline upstream artifact too: the accepted climate-zone model (`worldgen/climate.py`, fourteen Koppen-style zones read from Chris's warm/cold current drawing) as an indexed class raster `mapgen/derived/climate_zones.png`, its index, and `state_climate_index.json` (`--states`). Its settings (`config/climate_settings.json`, merged over `climate.DEFAULT`) are frozen by acceptance; the Earth calibration harness is not kept (provenance is in the module docstring). `--check` compares decoded pixels, not file bytes. **A regenerated `heightmap.png` or `land_sea_mask.png` moves the picture: `--check` goes stale, and the response is to render (`--render`, to `scratchpad/`), send the PNG and have Chris accept it again, never to loosen the check.** The drawing (`sources/geology/winds_and_currents.png`, source layer `climate_currents`) is Chris's; a stroke reaches only about 240 km from a coast. The zone-to-class mapping `config/climate_zone_class_map.json` is a first-draft prior, not lore: `tabulate_state_prior.py` reads it for the non-blocking `clim_*` columns and it assigns no state a class.
- `generate_arable_heatmap.py` is an offline upstream artifact (`mapgen/derived/arable_heatmap*.{png,json}`), not game-loaded; its rendered preview (`scratchpad/arable_on_globe.png`) is the acceptance gate. Known limitation: the field is built world-wide and the out-of-scope far-eastern heightmap carries baked-in label text as elevation; the Old World heightmap is clean.

### Rivers, lakes, impassable land, cities, hubs

- **Rivers** are source-driven: canon rivers are hand-traced as a pure-blue network (`full.ora#rivers`); `worldgen/river_network.py` orients each network into a flow DAG. A network the tool can't auto-orient is reported `no-source` and needs a manual entry in `mapgen/config/river_overrides.json`. Naming is opt-in via the optional `mapgen/config/canon_river_names.json` (and `river_sources.json`; `canon_rivers.csv` adds (river, state) coverage) — read only if present. A province regen does not invalidate `rivers.png`, but re-run `generate_rivers.py` after one if `rivers_index.json`'s `state_keys` must be current.
- **Lakes** are a third province class (`kind:"lake"`, impassable, stateless): declared only in `default.map`'s `lakes` block, never a `99_seas` state, water strategic region or loc.
- **Impassable land**: a flat-colour layer cut into one impassable province per connected paint tract. No pocket is cut around a canon city — the paint is taken as drawn, so a sealed-in city needs the paint reworked by hand (`render_canon_cities_preview.py` emits a transparent overlay for that). `validate_map._check_impassable_land` proves connectivity and canon-city reachability.
- **City blobs and seeding**: a painted city blob stays in one province (a blob straddling a state border or paint edge by more than 4px is a hard error; up to 4px is a graze); every city dot also seeds its own province (`city_dots`, skipped and logged when it lands on a keep-whole archipelago, placeholder region, impassable paint, or within `MIN_ANCHOR_SEP` of another seed; hub anchors win).
- **Lore hubs**: `mapgen/config/hub_worksheet.json` pins each named settlement to a canvas anchor; `generate_provinces.py` seeds a distinct province there (hard error on an anchor in water, in a keep-whole archipelago, or too close to another). A `stack_on: <host hub>` row shares its host's pixel. Any worksheet change forces the full `generate_provinces.py` → `generate_sea_regions.py` + `generate_land_regions.py` → re-validate cascade, since a seeded anchor reshuffles every province colour.
- **Adjacencies**: Chris draws non-touching crossings as flat yellow lines (`terraqueous_globe_reprojected - adjacencies.png`); each is typed by hand in `mapgen/config/adjacency_worksheet.json` (identity = endpoint coordinates, 4px tolerance; `type` `sea` or `canal_*`). `--review` (default) writes gitignored previews to `scratchpad/`; `--sync` re-anchors the worksheet after a redraw and never deletes (unmatched rows park under `stale`); `--write` emits; `--check` asserts current. An `artificial` canal additionally needs `common/buildings`/`common/production_methods` entries this schema does not author.

### Hand-authored inputs (edit deliberately, regenerate through — never inferred from generator output)

## Name citations: the `source` convention

Every hand-authored place name carries a **citation**, so canon can be told from invention without re-litigating it:

- `mapgen/config/hub_worksheet.json` — each `HubRow` has a required `source` (a canon citation or the literal `invented`); blank is a schema error. Canon names come first; coin one only where canon is silent, and flag it `invented`.
- `mapgen/config/land_regions_worksheet.csv` — a trailing `source` column, additive (blank is legal for names that predate the convention). `name` and `source` are carried across a regen together by the same anchor relocation (`render_land_regions_preview.py`), never separately.

A name from the TWW3 Old World mod region table is cited `canon: cr_oldworld_campaign/<slug> (TWW3 Old World mod region table)` (`SOURCE_TEMPLATE` in `mapgen/tww3_name_lookup.py`). That table is ChaosRobie's Old World mod. The lookup **never writes either file**: it emits suggestions into gitignored `scratchpad/` for a human to accept, because the registration it samples through is provisional and the table is settlement-scale while our regions are province-scale (a hit is often a town *inside* the region). Land not drawn in `sources/originals/tww3_old_world_mod_parchment_cropped.png` is out of scope for naming; its **alpha channel** is the extent (the bounding box is the whole image and proves nothing), and a name resolved outside it is discarded.

Canon-city anchors (`mapgen/config/canon_cities.json`) are read off Chris's cyan dots on `sources/terraqueous_globe_reprojected - canon_cities.png` (canvas frame; detect `g>170 & b>170 & r<130`, cluster centroids). On the Games Workshop map "Cragmere" is Karak Varn.

## Standing decisions and lessons

- **The picture is the gate.** Every offline check was green while the map was visually unusable; render, send, and wait for Chris's verdict ([core.md](core.md)).
- **Canvas.** Miller cylindrical, `Y0 = 2142.0` pinned to a line Chris drew (band +74.9°N/−57.4°S), 8192×3616; no installed mod deviates from vanilla's dimensions. Chris communicates geometry by drawing on a copy of a source image: recover markup by differencing against the clean source, and never register or list a markup file in `mapgen/SOURCES.md`.
- **Usable sources** are flat uniform fills (not hatching or brush strokes), PNG not JPEG, and the same pixel dimensions as an already-registered frame; warn before Chris spends effort on a map. Registration: whole-map fits inflate (silhouette IoU rewards land overlap, and by-eye landmarks are the bottleneck) — use Chris's paired anchor dots on the reprojected globe (thin-plate through exact-RGB dot centroids; the crop's binary alpha mask must be kept, and dimensions re-read every pass because he re-exports). A dot warp covers only the convex hull of its dots, so dots belong on the outermost coast; a sheet that reuses dot colours is paired by position, and a trace drawn on the same sheet is declared in the seed's `ignore_colours`.
- **Acceptance is by named region**: Bretonnia ≥15, Empire ≥30, Cathay ≥40 and so on, 600–700 land states in all (`mapgen/regions/named_regions.json`). Bind a name to geometry by anchor point snapped to land, never by contour id. Hierarchy: province < state < state_region < strategic/geographic region; aim for ~7 provinces per state_region in the drawn Old World.
- **Per-state hand-authored tables** key on the canon state key `STATE_<NAME>` plus the naming anchor (`anchor_x`/`anchor_y`), never the Hilbert STATE number or a province colour — both reshuffle on regen.
- **LFS.** Seven `map_data/` paths and the three generated DDS under `gfx/map/` are Git-LFS (see `.gitattributes`); a clone needs git-lfs (else 133-byte pointer files) and `core.longpaths` on Windows. Before rewriting history, back up with `git bundle create … --all`, not just a branch.
- **Symptom.** A coastline regen reporting "0 land regions" or 100% ocean means `--from-fill` was not passed.
