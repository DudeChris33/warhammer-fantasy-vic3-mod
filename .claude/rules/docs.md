# Docs Rules

## What's authored vs. generated

- `docs/*.log` (`effects.log`, `triggers.log`, `modifiers.log`, `event_targets.log`, `on_actions.log`, `custom_localization.log`) are generated by the game itself. Never hand-edit them; if they look stale, they need to be regenerated from the game, not patched.
- This project currently has no other authored documentation beyond `CLAUDE.md`, `.claude/rules/`, `memory.md`, and `planning/`.

## What gets updated when

- Script changes (`common/`, `events/`) — no doc update needed unless they change a project-specific convention worth capturing in `.claude/rules/scripting.md`.
- New reusable pattern established (e.g. first naming convention for a folder) — record it in the matching `.claude/rules/*.md` file so the next task doesn't reinvent it.
- Planning files (`planning/issues/`, `planning/requests/`) — updated by the `/issue`, `/request`, `/plan`, `/build` skills, not manually.

## Rules

- Read existing rule files before editing them — match their existing structure and tone.
- Only update what the change actually requires — no speculative additions.
- If a rule file states "none exists yet" and this change establishes the first instance of that convention, update the rule file to record it instead of leaving it stale.
