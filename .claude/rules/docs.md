# Docs Rules

**Read when:** you are editing `CLAUDE.md`, `.claude/rules/`, agents, skills, `memory.md` or `planning/`. **Covers:** what is authored vs generated, what gets updated when, and the Maestro mirror sync. Loads automatically when you open a matching file with the Read tool — a starting point, not a boundary: read any other guide that would help, and read a neighbour whenever your work touches its area.

**Related guides:**
- [core.md](core.md) — always-loaded guardrails and trust order
- [scripting.md](scripting.md) — where script conventions are recorded

## What's authored vs. generated

- `docs/*.log` (`effects.log`, `triggers.log`, `modifiers.log`, `event_targets.log`, `on_actions.log`, `custom_localization.log`) are generated by the game itself. Never hand-edit them; if they look stale, they need to be regenerated from the game, not patched.
- Authored documentation: `CLAUDE.md`, `.claude/rules/` (the two always-loaded files and the path-scoped guides), `memory.md`, `planning/`, plus tool-side docs `tools/MAP_RUNBOOK.md`, `tools/SOURCES.md`, `tools/PROVENANCE.md`, `tools/REGEN_SEA_ZONES_PROMPT.md`, `tools/rivers/README.md`, the `tools/fixtures` READMEs, and in-folder readmes such as `map_data/state_regions/state_regions.md` and `common/modifier_type_definitions/modifier_types.md`.

## What gets updated when

- Script changes (`common/`, `events/`) — no doc update needed unless they change a project-specific convention worth capturing in `.claude/rules/scripting.md`.
- New reusable pattern established (e.g. first naming convention for a folder) — record it in the matching guide (routing table in `CLAUDE.md`) so the next task doesn't reinvent it.
- Work-tracking records — the workspec, its `## Approach` (legacy name `## Plan`), and the activity trail — live on the **maestro board** and are updated by the `/maestro-task`, `/maestro-scope`, `/maestro-build` (and `/maestro-auto`, `/maestro-vibe`) skills via the maestro MCP, not by hand. `planning/` no longer tracks open work (see `CLAUDE.md`).
- **`.claude/rules/*.md` is mirrored to the maestro workspace (id 70) as `rule`-kind workspace docs** (`upsert_workspace_doc`, slugs `rules-core`/`rules-docs`/`rules-heraldry`/`rules-interface`/`rules-localization`/`rules-peoples`/`rules-scripting`/`rules-testing`; see the `rules-sync-maintenance` doc for the full mapping) so conventions survive a machine change and reach Maestro agents — Chris works on a single machine today; Claude Code's own rule-loading is per-machine, not synced. **Whenever a rule file changes, re-run `upsert_workspace_doc` for its matching slug** to push the update; a new rule file needs a new `rules-<name>` slug added to the mapping doc. Path-scoped guides load only when a matching file is Read, so keep every guardrail in `core.md`.

## Rules

- Read existing rule files before editing them — match their existing structure and tone.
- Only update what the change actually requires — no speculative additions.
- If a rule file states "none exists yet" and this change establishes the first instance of that convention, update the rule file to record it instead of leaving it stale.
