# Core Rules

These rules apply to all work in this repository. Non-negotiable.

## Determinism (multiplayer sync)

`.metadata/metadata.json` sets `multiplayer_synchronized: true`. Every scripted effect/trigger/event must produce identical results on every client from identical game state.

- Never use non-seeded randomness. Use the game's own `random_list` / `random` script effects (seeded from game state), never anything that reads real-world time, file system, or OS state.
- Never call debug/console-only effects (e.g. anything documented in `docs/effects.log` as debug-only) from shipped content.
- Never read or write outside this mod folder from script — Clausewitz script has no such capability, and nothing should be added that assumes it does.

## Script correctness

- Before using any effect, trigger, modifier, event target, on_action, or custom localization key, confirm it exists and check its exact scope/signature in the matching `docs/*.log` file. Do not guess syntax.
- Match input/output scopes exactly as documented in `docs/event_targets.log` — using a target in the wrong scope fails silently or crash-to-desktops.
- New `common/` database entries must live under the correct existing subfolder (e.g. new buildings → `common/buildings/`) — don't create new top-level folders without checking they don't already exist.

## Localization

- Every new user-facing key (event text, decision name, building name, loc-referenced modifier name, etc.) must get an entry in `localization/english/`.
- Overriding vanilla text goes in `localization/replace/english/`, never by editing base-game files directly (they aren't part of this repo).

## Forbidden Actions

- Do not hand-edit anything under `docs/` — it is generated by the game.
- Do not invent effects/triggers/modifiers not present in `docs/*.log`.
- Do not add non-deterministic behavior (see Determinism above).
- Do not commit personal/local absolute file paths into script, loc, or gui files.
- Do not `git add -A` or `git push` without being asked.

## Philosophy

- Read before editing — always check the relevant `docs/*.log` entry and any existing sibling files in the target folder first.
- Minimal changes — a bug fix touches the smallest set of files that fixes it; a feature touches only what's needed.
- Domain logic (what an effect/trigger/decision does) lives in `common/` and `events/`; presentation (text) lives in `localization/`; UI layout lives in `gui/` + `interface/`. Don't mix these — e.g. don't hardcode display text in script files.
- Confirm with the user when a design decision isn't already pinned down by a `## Plan` section.

## Trust Order

1. `docs/*.log` (what the game engine actually accepts)
2. `.claude/rules/`
3. Existing script patterns already committed in `common/`/`events/`

On conflict, fix the losing side and update it to match.

## Delivery Checklist

- [ ] Every effect/trigger/modifier/event target used is confirmed present in the matching `docs/*.log`
- [ ] New user-facing text has a `localization/english/` (or `localization/replace/english/`) entry
- [ ] No non-deterministic script added
- [ ] Mod loaded in-game and `logs/error.log` checked clean for this mod's files (see [testing.md](testing.md))
- [ ] Only specific, relevant files staged — no `git add -A`
- [ ] Board item landed at `review`/`done` with its activity trail updated (commits, verification) — via the maestro MCP, not a local file move
