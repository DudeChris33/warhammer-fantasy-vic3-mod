# Warhammer Fantasy Overhaul

A total-conversion mod for Victoria 3 (supported game version 1.13.8), reskinning the base game into the Warhammer Fantasy setting using Clausewitz script (`.txt`), the PDX GUI format (`.gui`), and localization YAML (`.yml`). Multiplayer-synchronized (`.metadata/metadata.json`), so scripted content must stay deterministic across clients.

## Canonical entry point

`docs/*.log` are game-generated reference dumps and are the authority on what script syntax is valid — read the relevant one before writing any script that uses it:

| File | Covers |
|---|---|
| `docs/effects.log` | All valid effects |
| `docs/triggers.log` | All valid triggers/conditions |
| `docs/modifiers.log` | All valid static modifiers |
| `docs/event_targets.log` | Scope-linking event targets |
| `docs/on_actions.log` | Game-fired on_action hooks |
| `docs/custom_localization.log` | Custom localization definitions |

These are read-only references generated by the game itself — never hand-edit them.

## Project layout

| Path | Contents |
|---|---|
| `common/` | Script "database" definitions — buildings, cultures, decisions, laws, technologies, scripted_effects/triggers/values, history, etc. One subfolder per game database. |
| `events/` | Event script files (`.txt`) |
| `gui/` | Custom UI widget definitions (`.gui`) |
| `interface/` | `.gfx` sprite/icon definitions referenced by `gui/` |
| `gfx/` | Art assets — flags, interface icons, loadingscreens, map, models, particles, portraits |
| `localization/english/` | Loc entries for new content (`.yml`, `l_english:` header) |
| `localization/replace/english/` | Loc entries that override base-game vanilla text |
| `map_data/` | Map/state region modifications |
| `music/`, `sound/` | Audio assets |
| `.metadata/metadata.json` | Mod descriptor (name, id, version, supported game version, tags) |
| `docs/` | Read-only game-generated script reference (see above) |
| `planning/` | Issue/request/plan tracking (see below) |
| `tools/` | Offline map generator + validator toolchain (Python — Pillow/numpy). **Not loaded by the game**; kept out of mod content folders. Run `tools/validate_map.py` before committing map text; see `tools/MAP_RUNBOOK.md` for the desktop-client steps. |

All `common/*` and top-level content folders currently contain only `.gitkeep` — no script content has been authored yet.

## How to work here

- **Rules** in `.claude/rules/*.md` are loaded automatically. Follow them.
- **Skills** in `.claude/skills/` invoked with `/<name>`:
  - `/issue <description>` — investigate + document a bug
  - `/request <description>` — explore + document a feature request
  - `/plan <path/to/file.md>` — design implementation approach
  - `/build <path/to/file.md>` — implement, test, commit, review
  - `/project-memory` — show memory state
- **Sub-agents** in `.claude/agents/` are spawned by `/build`:
  - `docs-updater` — update docs from diff
  - `security-review` — review diff for MP-desync and content-integrity risks

## Workflow chain

```
Bug or feature idea
      │
      ▼
/issue or /request  ── writes ──►  planning/issues/ or planning/requests/
      │
      ▼
/plan             ── appends ─►  ## Plan section
      │
      ▼
/build            ── appends ─►  ## Resolution, moves to planning/done/
```

`/plan` must never be skipped — it's where file-level decisions get pinned down.

## Planning directory

- `planning/issues/` — open bugs
- `planning/requests/` — open feature requests
- `planning/done/` — resolved, with `## Resolution` filled in
- `planning/future/` — backlog, not yet actionable
- `planning/rejected/` — declined

## Trust order

On conflict, in this order: `docs/*.log` (what the game engine actually accepts) → `.claude/rules/` → existing script patterns already committed in `common/`/`events/`. Fix the losing side and update it to match.

## Build + test

There is no compiler and no automated test suite — Clausewitz script has no offline validator. Validation is: load the mod in Victoria 3 and check `../../logs/error.log` (relative to this mod folder, i.e. `Documents/Paradox Interactive/Victoria 3/logs/error.log`) for script/loc parse errors after every change that touches `common/`, `events/`, `gui/`, or `localization/`. Treat any new line in that log referencing this mod's files as a build failure.

## Non-negotiables

- Read before editing — always check `docs/*.log` for the exact effect/trigger/modifier signature before using it.
- No drive-by refactors — don't touch unrelated files or folders.
- No `git add -A` — stage specific files only.
- No `git push` unless asked.
- Never hand-edit files in `docs/` — they're generated by the game, not authored.
- Preserve determinism: avoid non-seeded randomness or anything that could desync a multiplayer-synchronized mod.
- Never leave a `{{...}}` placeholder or invented content — if `docs/*.log` doesn't confirm an effect/trigger exists, don't use it.
